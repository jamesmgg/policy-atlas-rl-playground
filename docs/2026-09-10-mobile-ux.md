# Mobile navigation update

The previous mobile layout stacked the desktop workspace into one long page.
At 390 × 844, the project library began about 1,189 pixels below the top and
training controls about 2,098 pixels below it. Both projects and top runs used
horizontal carousels, making discovery and switching unnecessarily difficult.

## Changes

- Four distinct mobile screens: Projects, Watch, Train, and Results. Persistent
  bottom navigation shows the current screen, and the header always identifies
  the current project with a Switch action.
- A vertical, searchable project list with category filters, a visible current
  selection, and a clear-filters action for empty searches.
- Training controls come before the experiment brief. Starting a run opens Watch;
  replay selection does the same. Watch offers direct training, pause, and results
  actions. Saved runs are stacked vertically on phones.
- Screen changes return to the top and focus the screen heading. URL hashes
  support direct links and browser history, including the older section links.
  Controls and filter state stay mounted while moving between screens.
- Failed project switches retain the current project and screen. Mobile errors
  appear above the bottom navigation so a scrolled project list cannot hide them.
- Hidden canvases suspend their animation loop, checking visibility at 5 Hz
  instead of continuing to render frames while another screen is open.
- Stale WebSocket callbacks cannot clear or overwrite a replacement connection.
  Testing exposed this race during a development refresh; training controls had
  appeared connected even though their active socket reference was lost.

## Verification

- All 29 frontend tests pass, including new and legacy mobile URL routing.
- TypeScript and the production Vite build pass; `git diff --check` passes.
- Browser checks at 320 × 568, 390 × 844, 768 × 1024, and 1440 × 1000 found no
  horizontal page overflow. Desktop retains its three-column workspace.
- Verified project filtering, empty-search recovery, selection, heading focus,
  Back navigation, and retained training controls while changing screens.
- In a disposable backend, started a two-episode Ball & Beam run, opened its
  saved replay from Results, returned to Watch, and stopped the replay.
- Stopped that disposable backend and attempted a different project: the
  original project remained selected, Projects stayed open, and the error was
  visible above the navigation and could be dismissed.
- Opened learning diagnostics and changed screens without browser warnings.

Only the frontend is deployed for this change. The live backend, saved policies,
and active experiment are not reset or restarted by the update.
